المزوّدون

مزوّد OpenAI — GPT وسلسلة o والواجهات المتوافقة

اضبط مزوّد OpenAI في Nexora لاستخدام GPT-4o ونماذج الاستدلال من سلسلة o أو أي واجهة متوافقة مع OpenAI بتحكم كامل في مفتاح API والعنوان.

يربط نوع المزوّد OpenAI تطبيق Nexora بواجهة Chat Completions أو Responses من OpenAI. ولأن بروتوكول OpenAI أصبح معيارًا في الصناعة، فإن نوع المزوّد نفسه يعمل مع عشرات الخدمات الخارجية — يكفي تغيير عنوان Base URL. تركّز هذه الصفحة على الاتصال المباشر بـ OpenAI؛ وللإعدادات الخارجية والمحلية راجع المزوّدين المخصصين / المتوافقين مع OpenAI.

أضف مزوّد OpenAI

افتح إعدادات المزوّدين

انتقل إلى Settings ← Providers واضغط Add Provider.

اختر OpenAI

اختر OpenAI من قائمة أنواع المزوّدين.

أدخل مفتاح API

الصق مفتاح OpenAI API في حقل API Key. يمكنك العثور على المفاتيح أو إنشاؤها من platform.openai.com/api-keys.

تأكد من عنوان Base URL

القيمة الافتراضية لعنوان Base URL هي https://api.openai.com/v1. اتركها كما هي للاتصال القياسي بـ OpenAI.

أضف النماذج

اضغط Add Model، وأدخل معرّف النموذج (مثل gpt-4o أو o3)، واضبط اسم العرض والقدرات، ثم احفظ. كرّر ذلك لكل نموذج تريد استخدامه.

احفظ

اضغط Save لتطبيق التغييرات. سيظهر المزوّد ونماذجه الآن في منتقي النموذج.

مرجع الإعدادات

الحقول الأساسية

apiKeystringrequired

مفتاح OpenAI API الخاص بك. يحفظه Nexora محليًا على جهازك ولا يرسله إلا إلى عنوان Base URL المضبوط. يدعم تدوير المفاتيح المفصولة بفواصل (مثل sk-key1,sk-key2) عند امتلاكك عدة مفاتيح.

baseUrlstringdefault: https://api.openai.com/v1

الرابط الجذر لواجهة API المتوافقة مع OpenAI. غيّره عند الاتصال بوسيط أو بخدمة خارجية تحاكي واجهة OpenAI.

chatCompletionsPathstringdefault: /chat/completions

المسار الذي يُلحق بعنوان Base URL لطلبات المحادثة. غيّره فقط إذا كان مزوّدك يستخدم مسارًا غير قياسي.

الحقول المتقدمة

useResponseApibooleandefault: false

التبديل من نقطة Chat Completions إلى واجهة Responses الأحدث من OpenAI. فعّل هذا للنماذج التي تدعم Responses API فقط، مثل المقدَّمة عبر نقطة Grok من xAI.

includeHistoryReasoningbooleandefault: true

عند التفعيل، يضمّن Nexora المحتوى reasoning_content من ردود المساعد السابقة عند إرسال سجل المحادثة. عطّله إذا كان مزوّدك يرفض الرسائل التي تحتوي حقول الاستدلال.

التحقق من الرصيد

فعّل التحقق من الرصيد لعرض رصيد API المتبقي مباشرة في شاشة تفاصيل المزوّد.

balanceOption.enabledbooleandefault: false

شغّل عرض الرصيد لهذا المزوّد.

balanceOption.apiPathstringdefault: /credits

المسار (نسبةً إلى Base URL) أو الرابط الكامل المستخدم لجلب رصيدك. القيم الشائعة:

  • /credits — OpenRouter
  • /user/balance — DeepSeek
  • /user/info — SiliconFlow
balanceOption.resultPathstringdefault: data.total_usage

مسار بصيغة النقاط داخل استجابة JSON يشير إلى قيمة الرصيد الرقمية. مثلًا، يُحسب data.total_credits - data.total_usage لـ OpenRouter، وbalance_infos[0].total_balance لـ DeepSeek.

ترويسات HTTP مخصصة

يمكنك إرفاق ترويسات HTTP إضافية بكل طلب يرسله هذا المزوّد. افتح قسم Custom Headers في شاشة تفاصيل المزوّد وأضف أزواج المفتاح والقيمة. هذا مفيد لأنظمة المصادقة التي تتطلب ترويسات إضافية (مثل HTTP-Referer مع OpenRouter) أو للوسطاء في الشركات.

حقول مخصصة في جسم الطلب

يتيح لك قسم Custom Body حقن حقول JSON إضافية في كل طلب محادثة. استخدمه لتمرير معاملات خاصة بالمزوّد لا يعرضها Nexora كإعدادات أساسية — مثل safe_mode لبعض النقاط المزوّدة بالإشراف أو معاملات أخذ العينات الخاصة بمزوّد معيّن.

تحقق من اتصالك

بعد الحفظ، افتح شاشة تفاصيل المزوّد واضغط Test Connection. يرسل Nexora طلبًا بسيطًا إلى عنوان Base URL ويخبرك هل قُبل مفتاح API. إذا فشل الاختبار، فراجع مفتاح API وعنوان Base URL.

ليست كل الواجهات المتوافقة مع OpenAI تنفّذ مسار قائمة /models. إذا لم يعمل اكتشاف النماذج، فأضف معرّفات النماذج يدويًا بالمعرّف الدقيق الذي يتوقعه المزوّد.

مثال: الاتصال بـ OpenRouter عبر النوع OpenAI

استخدم نوع المزوّد OpenAI، واضبط Base URL على https://openrouter.ai/api/v1، وأضف مفتاح OpenRouter API، واختياريًا أضف HTTP-Referer وX-Title كترويسات مخصصة. راجع المزوّدين المخصصين لشرح كامل.
